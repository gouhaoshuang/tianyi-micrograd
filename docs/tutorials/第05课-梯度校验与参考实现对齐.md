## 2. 正确性证据来自哪里

| 方法              | 怎么做                             | 能说明什么                           |
| ----------------- | ---------------------------------- | ------------------------------------ |
| 手算              | 独立推导具体表达式的值和导数       | 小例子是否符合链式法则               |
| 有限差分          | 只用普通浮点前向函数，逐个扰动输入 | 组合表达式的自动梯度是否接近数值导数 |
| 可选 PyTorch 对照 | 同一表达式交给两个引擎，各自反传   | 是否与另一个自动求导实现一致         |

前两项不依赖 PyTorch。对照测试也不把 PyTorch 接入自己的引擎，只把它作为计算另一份结果的工具。

通过几个小例子不能证明所有输入都正确，但这些检查可以覆盖共享节点、分支、混合运算和多变量梯度，给下一课提供可靠起点。

## 3. 第一步：复现参考仓库的表达式

参考 [原仓库的第一个测试](/data/ghs/projects/micrograd/test/test_engine.py:4)，保持相同的表达式，先用独立算出的结果检查。

手动创建 `test_gradcheck.py`，写入：

```python
from math import isclose

from tianyi_micrograd.engine import Value


def test_reference_expression():
    x = Value(-4.0)
    z = 2 * x + 2 + x
    q = z.relu() + z * x
    h = (z * z).relu()
    result = h + q + q * x
    result.backward()

    assert result.data == -20.0
    assert x.grad == 46.0
```

为什么是这两个数？在 `x=-4` 附近，`z=3*x+2` 为负，`z*z` 为正，所以两个 ReLU 所在分支都确定：

```text
z=-10，q=40，h=100
result=100+40+40*(-4)=-20

当前分支可化简为 result=3*x**3+14*x**2+14*x+4
导数为 9*x**2+28*x+14，在 x=-4 处等于 46
```

这里没有从自己的引擎反推出预期答案，也没有导入原版 `Value`。测试中的多次使用 `x`、`z`、`q`，会同时检查图上的多条梯度路径。

## 4. 第二步：用中心差分检查多变量梯度

选择一个包含乘法、幂、除法与 ReLU 的函数：

```text
f(a,b) = [max(0,a*b)+a**3] / (b+2)
```

对 `a` 求偏导时，只改变 `a`；对 `b` 求偏导时，只改变 `b`：

```text
df/da ≈ [f(a+h,b)-f(a-h,b)] / (2*h)
df/db ≈ [f(a,b+h)-f(a,b-h)] / (2*h)
```

选择两个离 ReLU 切换点足够远的位置：

|    a |   b | a*b 的符号 | f 的值 | df/da | df/db |
| ---: | --: | ---------- | -----: | ----: | ----: |
|  1.5 | 0.5 | 正         |   1.65 |   2.9 | -0.06 |
| -1.5 | 0.5 | 负         |  -1.35 |   2.7 |  0.54 |

这让我们分别检查 ReLU 打开和关闭时的梯度。不要在 `a*b=0` 处用中心差分要求它匹配项目选择的零点梯度；那里不可导。

### 在同一文件中追加浮点函数和测试

`isclose` 与 `Value` 已在文件开头导入，下面不重复添加导入：

```python
def objective(a, b):
    return (max(0.0, a * b) + a**3) / (b + 2)


def test_finite_difference():
    h = 1e-6
    for a0, b0 in [(1.5, 0.5), (-1.5, 0.5)]:
        a = Value(a0)
        b = Value(b0)
        loss = ((a * b).relu() + a**3) / (b + 2)
        loss.backward()

        da = (objective(a0 + h, b0) - objective(a0 - h, b0)) / (2 * h)
        db = (objective(a0, b0 + h) - objective(a0, b0 - h)) / (2 * h)

        assert isclose(loss.data, objective(a0, b0), rel_tol=1e-12, abs_tol=1e-12)
        assert isclose(a.grad, da, rel_tol=1e-5, abs_tol=1e-6)
        assert isclose(b.grad, db, rel_tol=1e-5, abs_tol=1e-6)
```

`objective()` 只接收普通浮点数，使用 Python 的 `max` 和算术，不调用自己的 `Value`。所以差分结果不依赖自己的反传规则，也没有复用自己的前向运算方法。

`a0`、`b0` 是不变的检查位置；`a`、`b` 是本轮新建的节点。不要在旧图上反复改 `.data` 后调用 `backward()`。

### 为什么有两组容限

前向结果直接对照同一个数学函数，容限可以较紧。中心差分包含近似与浮点舍入误差，梯度容限稍宽。

`isclose(actual, expected, rel_tol=..., abs_tol=...)` 同时允许相对误差和绝对误差，后者能照顾接近零的数。两者取较宽的允许范围，不是要求同时满足两条独立界限。

`h` 太大会增加近似误差，太小又可能让相近数相减的舍入误差占主导。本例取 `1e-6`，不要把这个步长当作所有函数通用的最优值。

## 6. 选做：用 PyTorch 对齐参考仓库的组合表达式

原仓库的 [第二个测试](/data/ghs/projects/micrograd/test/test_engine.py:28) 包含更多混合运算。这里用同一数学表达式分别建立自己的图和 PyTorch 图。

愿意做对照时，手动创建 `test_engine_torch.py`，写入下面的完整内容。这个文件不被核心实现导入，也不需要修改项目依赖声明：

```python
from math import isclose

import pytest

from tianyi_micrograd.engine import Value


def reference_expression(a, b):
    c = a + b
    d = a * b + b**3
    c = c + (c + 1)
    c = c + (1 + c + (-a))
    d = d + (d * 2 + (b + a).relu())
    d = d + (3 * d + (b - a).relu())
    f = (c - d)**2
    return f / 2.0 + 10.0 / f


def test_torch_reference():
    torch = pytest.importorskip("torch")
    a, b = Value(-4.0), Value(2.0)
    result = reference_expression(a, b)
    result.backward()

    ta = torch.tensor(-4.0, dtype=torch.float64, requires_grad=True)
    tb = torch.tensor(2.0, dtype=torch.float64, requires_grad=True)
    expected = reference_expression(ta, tb)
    expected.backward()

    for actual, target in [(result.data, expected.item()),
                           (a.grad, ta.grad.item()),
                           (b.grad, tb.grad.item())]:
        assert isclose(actual, target, rel_tol=1e-9, abs_tol=1e-6)
```

几个要点：

- `pytest.importorskip("torch")` 在测试执行时导入 PyTorch；没有安装时跳过此测试，不要求安装。
- 使用 CPU `float64` 与 Python 浮点比较，避免把默认较低精度的差异误判为引擎错误。
- `requires_grad=True` 让 PyTorch 记录它自己的图；自己的引擎仍完全使用 `Value`。
- `.item()` 从单元素 Tensor 中取出普通数值，便于比较输出与两个叶节点的梯度。
- 原例的 `+=` 改写为重新绑定。对自己的 `Value` 数学意义相同，也避免复用表达式时触发 PyTorch 的原地修改行为。

运行：

```bash
python -m pytest test/tianyi_micrograd/test_engine_torch.py -q
```

安装有 PyTorch 时应为 `1 passed`，没有时应为 `1 skipped`，以实际结果为准。主线两个测试不导入 PyTorch。

## 7. 常见问题与验收

| 现象                       | 优先检查                                       |
| -------------------------- | ---------------------------------------------- |
| 数值差分也调用了 Value     | 改为普通浮点函数，保持验证路径独立             |
| 一个偏导正确，另一个错误   | 是否只扰动对应的变量；是否把两次差分的输入写反 |
| ReLU 零点差分与反传不一致  | 换到可导点，零点约定由第 04 课的测试检查       |
| 改小 h 后误差更大          | 可能受到舍入误差影响，不要无限减小步长         |
| 换一组点就出现莫名累加     | 每组点是否重新创建节点，并只反传一次           |
| 对照通过却导入了 micrograd | 确认测试导入的是自己的`tianyi_micrograd`     |

最后运行已有测试：

```bash
python -m pytest test -q
```

验收时说明：手算、有限差分和另一个求导引擎分别提供什么证据；为什么两个偏导要分别扰动；为什么跳过 PyTorch 对照不会阻止进入下一课。
