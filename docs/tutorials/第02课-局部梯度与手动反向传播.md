## 2. 核心原理：链式法则与梯度回传

设目标函数为 $L$，当前运算为 $out = f(x, y)$。

由微积分的**链式法则**，最终目标对输入的梯度为：

$$
\frac{\partial L}{\partial x} = \frac{\partial L}{\partial out} \cdot \frac{\partial out}{\partial x}
$$

对应代码中的变量关系为：

$$
\text{x.grad} += \text{out.grad} \times \frac{\partial out}{\partial x}
$$

### 基础运算的求导与回传规则

| 运算                                 | 局部导数 ($\frac{\partial out}{\partial x}, \frac{\partial out}{\partial y}$) | 梯度回传公式 ($\text{grad}$ 累加) |                                                                                                                     |
| :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| **加法** ($out = x + y$)     | $\frac{\partial out}{\partial x} = 1$<br /> $\frac{\partial out}{\partial y} = 1$                                 | $x.\text{grad} \mathrel{+}= 1 \cdot \text{out.grad}$<br /> $y.\text{grad} \mathrel{+}= 1 \cdot \text{out.grad}$ |
| **乘法** ($out = x \cdot y$) | $\frac{\partial out}{\partial x} = y$<br /> $\frac{\partial out}{\partial y} = x$                                 | $x.\text{grad} \mathrel{+}= y \cdot \text{out.grad}$<br /> $y.\text{grad} \mathrel{+}= x \cdot \text{out.grad}$ |

**注意**：由于多条计算路径会汇聚到一个变量，总梯度为各路径贡献之和，因此必须使用 `+=` 累加，不可直接覆盖。

## 3. 第一步：给每个节点预留反传函数

在 `Value` 类中，将原来的 `__init__` 替换为下面的方法，只增加 `_backward` 这一行：

```python
    def __init__(self, data, _children=(), _op=""):
        self.data = data
        self.grad = 0
        self._prev = set(_children)
        self._op = _op
        self._backward = lambda: None
```

`lambda: None` 创建一个不接收参数、返回 `None` 的函数。这里把函数保存到属性中，并没有立即调用它。

直接创建的 `Value(2.0)` 是叶节点，没有更早的运算需要传播，所以它的 `_backward()` 什么也不做。加乘产生的结果节点，稍后会把这个空函数换成自己的反传规则。

注意区分：

- `node._backward`：取出保存的函数。
- `node._backward()`：现在执行这个函数。

## 4. 第二步：给加法保存局部反传规则

在同一个 `Value` 类中，用下面的方法替换原来的 `__add__`，不要保留两份同名方法：

```python
    def __add__(self, other):
        out = Value(self.data + other.data, (self, other), "+")

        def _backward():
            self.grad += out.grad
            other.grad += out.grad

        out._backward = _backward
        return out
```

前向数值和节点连接没有改变，增加的是三件事：

1. 在方法里面定义一个局部函数 `_backward`。
2. 这个函数知道要把 `out.grad` 累加给两个输入。
3. 将函数保存在结果节点上，等待后面调用。

### 4.1 为什么函数里没有参数，也能找到输入？

内层 `_backward` 使用了外层方法中的 `self`、`other`、`out`。即使 `__add__` 已经返回，保存下来的函数仍能访问这些对象。这就是这里用到的**闭包**。

对于 `d=e+c`，这个函数记住的对应关系是：

```text
self  → e
other → c
out   → d
```

调用 `d._backward()` 时，它读取当时的 `d.grad`，再累加到 `e.grad`、`c.grad`。它不会继续自动调用 `e._backward()`。

### 4.2 为什么赋值时不加括号？

`out._backward = _backward` 保存函数，留待反传时执行。

如果写成 `out._backward = _backward()`，函数会在前向计算时立即执行，并把返回值 `None` 存到属性里；以后再调用就会出错。

这里保存的是实例属性中的普通函数，输入对象已由闭包关联，不需要给内层函数再传一个 `self` 参数。

## 5. 第三步：给乘法保存局部反传规则

将原来的 `__mul__` 替换为：

```python
    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other), "*")

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad

        out._backward = _backward
        return out
```

乘法对一个输入的局部导数，是另一个输入的数值。比如 `e=a*b`，若 `e.grad=-2`，则：

```text
a 获得的贡献 = b.data*e.grad = -3*(-2) =  6
b 获得的贡献 = a.data*e.grad =  2*(-2) = -4
```

这个闭包在执行时读取输入的 `.data`。因此本课从前向计算到反传结束，不要修改这些节点的数值；否则会把新数值用于旧计算图的导数计算。

到这里，`engine.py` 只改了三个方法，`__repr__` 不变，也还没有添加 `backward()`。

## 6. 第四步：亲手按顺序传回梯度

沿用之前的表达式：

```text
e = a*b = -6
d = e+c =  4
L = d*f = -8
```

前向顺序是 `e → d → L`；现在手动反过来执行 `L → d → e`。

在终端运行下面的实验。每次运行都重新创建节点，避免上一次留下的梯度干扰：

```bash
python - <<'PY'
from tianyi_micrograd.engine import Value

a = Value(2.0)
b = Value(-3.0)
c = Value(10.0)
f = Value(-2.0)
e = a * b
d = e + c
loss = d * f

loss.grad = 1
loss._backward()
d._backward()
e._backward()

print("L =", loss.data)
for name, node in (("a", a), ("b", b), ("c", c), ("f", f)):
    print(f"{name}.grad = {node.grad}")
PY
```

预期输出：

```text
L = -8.0
a.grad = 6.0
b.grad = -4.0
c.grad = -2.0
f.grad = 4.0
```

先设置 `loss.grad=1`，因为 `dL/dL=1`。如果保留初始值 `0`，后面各步乘到的上游梯度就都是零。

你可以逐步观察每次调用后发生的变化：

| 操作                 | 本步传给输入的梯度           |
| -------------------- | ---------------------------- |
| `loss._backward()` | `d.grad=-2`，`f.grad=4`  |
| `d._backward()`    | `e.grad=-2`，`c.grad=-2` |
| `e._backward()`    | `a.grad=6`，`b.grad=-4`  |

### 为什么顺序不能乱？

如果先调用 `e._backward()`，此时 `e.grad` 还是零，传给 `a`、`b` 的贡献也就是零。后面再改 `e.grad`，已经执行过的函数不会自动重新运行。

本课先手动安排顺序。下一课再通过拓扑排序，让 `backward()` 自动安排。

## 7. 为什么必须用 +=：同一个输入出现两次

考虑 `x=3` 时的 `out=x*x`。乘法闭包中的 `self`、`other` 都指向同一个 `x`。

当 `out.grad=1` 时，两行累加分别执行：

```text
第一行：x.grad 从 0 变为 3
第二行：x.grad 从 3 变为 6
```

这正好得到 `d(x*x)/dx=2*x=6`。如果两行都写成赋值 `=`，第二次会覆盖第一次，只剩下 `3`。

`x+x` 也是一样：两条贡献分别是 `1`，合起来应为 `2`。

虽然 `_prev` 集合把两个相同的 `x` 去重为一个节点，运算闭包仍分别处理两个操作数。**输入节点的去重，不会取消操作数对应的梯度贡献。**

这里讨论的是一次反传中的贡献累加。暂时不要在同一张图上反复调用这些函数；本课每个实验都新建图，每个局部反传只调用一次。

## 8. 第五步：追加两个简短测试

在 `/data/ghs/projects/tianyi-micrograd/test/tianyi_micrograd/test_value.py` 末尾追加下面两个函数。保留已有的两个前向测试，文件开头已有 `Value` 的导入，不需要重复添加。

```python
def test_manual_backward():
    a = Value(2.0)
    b = Value(-3.0)
    c = Value(10.0)
    f = Value(-2.0)
    e = a * b
    d = e + c
    loss = d * f

    loss.grad = 1
    loss._backward()
    d._backward()
    e._backward()

    assert (a.grad, b.grad, c.grad, f.grad) == (6.0, -4.0, -2.0, 4.0)


def test_repeated_operand_backward():
    x = Value(3.0)
    out = x + x
    out.grad = 1
    out._backward()
    assert x.grad == 2.0

    x = Value(3.0)
    out = x * x
    out.grad = 1
    out._backward()
    assert x.grad == 6.0
```

## 9. 常见问题

| 现象                                  | 检查位置                                               |
| ------------------------------------- | ------------------------------------------------------ |
| 所有梯度都是零                        | 是否设置`loss.grad=1`；是否按输出到输入的顺序调用    |
| `'NoneType' object is not callable` | 是否误写成`out._backward = _backward()`              |
| 加法正确，乘法梯度不对                | 是否乘上“另一个输入”的`.data` 与 `out.grad`      |
| `x*x` 得到 `3`，不是 `6`        | 是否把`+=` 写成了 `=`                              |
| 反复实验时结果越来越大                | 是否复用了旧节点或重复调用局部反传；重新创建整张图再试 |
