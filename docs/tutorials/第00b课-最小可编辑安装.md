# 第 00b 课：最小可编辑安装

目标：把自己的项目安装到 conda `agent` 环境，以后可以直接 `import tianyi_micrograd`，无需每次设置 `PYTHONPATH`。

**本课由你手动创建配置、执行安装。Agent 只编写教程，没有替你安装。**

## 1. 确认最小目录

```text
/data/ghs/projects/tianyi-micrograd/
├── pyproject.toml                 # 本课手写
└── src/
    └── tianyi_micrograd/
        └── __init__.py            # 可以留空
```

已有的文件保留。如果包目录和 `__init__.py` 尚不存在，手动创建即可；不需要先写 `Value`，`engine.py` 可以在第 01 课实现。

## 2. 手写 pyproject.toml

在项目根目录手动创建 `/data/ghs/projects/tianyi-micrograd/pyproject.toml`，写入完整内容：

```toml
[build-system]
requires = ["setuptools>=64"]
build-backend = "setuptools.build_meta"

[project]
name = "tianyi-micrograd"
version = "0.1.0"

[tool.setuptools.packages.find]
where = ["src"]
```

只需理解三部分：

- `[build-system]`：使用 setuptools 构建、安装这个项目；它是构建工具，不参与模型计算。
- `[project]`：声明安装用的项目名与版本。安装名称是 `tianyi-micrograd`，Python 导入名称仍是 `tianyi_micrograd`，后者来自包目录名。
- `where = ["src"]`：在 `src/` 下寻找要安装的包。

这些配置写法见 [setuptools 官方说明](https://setuptools.pypa.io/en/latest/userguide/pyproject_config.html)。本课不需要添加 PyTorch 或其他运行时依赖。

## 3. 在 agent 环境中安装

在终端执行：

```bash
conda activate agent
cd /data/ghs/projects/tianyi-micrograd
python -c 'import sys; print(sys.executable)'
```

确认解释器为 `/data/ghs/miniconda3/envs/agent/bin/python`，再执行：

```bash
python -m pip install -e . --no-build-isolation
```

- `python -m pip`：使用当前 Python 环境中的 pip。
- `-e`：可编辑安装，让环境关联当前源码，之后修改 Python 源码，重新运行程序即可使用新内容。
- `.`：安装当前目录的项目。
- `--no-build-isolation`：直接使用 `agent` 环境已有的构建工具。本次只读检查确认已有 setuptools `81.0.0` 和 wheel `0.46.3`。

安装会写入当前环境，并可能在项目中生成 `.egg-info` 等元数据，这是安装产生的文件。以后修改版本、依赖等配置，需要重新执行安装命令。可编辑安装的行为见 [setuptools 官方说明](https://setuptools.pypa.io/en/latest/userguide/development_mode.html)。

## 4. 验证安装是否生效

仍在项目根目录执行：

```bash
env -u PYTHONPATH python -c 'import tianyi_micrograd; print(tianyi_micrograd.__file__)'
```

`env -u PYTHONPATH` 只对本次命令移除该环境变量，避免旧的路径设置影响验证，不修改你的终端配置。

预期输出：

```text
/data/ghs/projects/tianyi-micrograd/src/tianyi_micrograd/__init__.py
```

这说明导入对应的是你自己的源码。以后在同一个 `agent` 环境运行测试，可以直接使用：

```bash
python -m pytest test -q
```

没有测试文件时，先完成第 01 课，再运行测试；不需要为本课额外写测试函数。

## 5. 让编辑器使用同一个环境

在 VS Code 命令面板执行 `Python: Select Interpreter`，选择：

```text
/data/ghs/miniconda3/envs/agent/bin/python
```

然后执行 `Python: Restart Language Server`，查看导入提示是否消失。

如果第 4 步已通过，但 Pylance 仍无法识别，确认解释器一致后，可以在项目根目录尝试兼容安装：

```bash
python -m pip install -e . --no-build-isolation --config-settings editable_mode=compat
```

Pylance 能识别基于路径的 `.pth` 文件，无法跟随需要执行 Python 的导入钩子；兼容模式可用于处理这种差异，见 [Pyright 导入说明](https://github.com/microsoft/pyright/blob/main/docs/import-resolution.md#editable-installs)。`compat` 是过渡方式，只在确实遇到此问题时使用，见 [setuptools 的说明](https://setuptools.pypa.io/en/latest/userguide/development_mode.html#legacy-behavior)。

本课验收只看两点：**不设置 `PYTHONPATH` 能导入自己的包；编辑器能定位到自己的源码。** 安装成功不代表自动求导或测试已经实现。
